# Аналитика рекламы и контроль ведения CRM (Битрикс24)

**Статус:** план на месяц (октябрь 2026)
**Цель:** чтобы реклама окупалась — менеджеры корректно обрабатывают лиды и заполняют CRM, а аналитика показывает реальную картину.

## 1. Контрольный период при запуске рекламы
- Заложить несколько часов на мониторинг в первые дни/недели рекламы.
- Проверить, как заполняются данные (источник, UTM, стадии, поля, причины отказа).
- Выявить ошибки и дать обратную связь отделу продаж по ведению CRM.

## 2. Контроль обработки лидов (скорость и дисциплина ОП)
- Медианное время до первого контакта с лидом.
- Среднее количество попыток связи.
- Количество и доля необработанных лидов.

## 3. Показатели эффективности рекламы
| Показатель | Что считаем |
|---|---|
| CPL | расход / кол-во лидов |
| CPQL | расход / кол-во квалифицированных лидов |
| CPA / CPS | расход / целевые действия (продажи) |
| ROAS | выручка / расход на рекламу |
| AOV | средний чек |
| LTV | суммарная выручка с клиента за всё время |
| Цикл сделки | средняя и медианная длительность |

## 4. Структура обращений
- Количество новых уникальных и повторных обращений.
- Разделение новых и повторных — на выбор:
  - **Вариант А:** две воронки — «Новые» и «Повторные» (повторники находят сами, новые теряются — их проще контролировать отдельно).
  - **Вариант Б:** одна воронка + автоматическое поле «Повторная сделка» для фильтрации новых лидов.

## 5. Причины потерь
- Справочник и обязательное поле «Причина неквалификации лида».
- Справочник и обязательное поле «Причина проигрыша сделки».

## 6. Телефония
- Настроить отслеживание звонков WhatsApp (фиксация в CRM).

## Что нужно для реализации
- Обязательные поля и справочники причин; автоопределение повторного обращения.
- Учёт расходов на рекламу по каналам (для CPL/CPQL/ROAS).
- Отчёты/дашборд в BI-конструкторе или аналитике Битрикс24.
- Регламент для ОП: SLA на первый контакт, минимум попыток связи.
- Решение клиента: две воронки или одна с полем «Повторная сделка».
