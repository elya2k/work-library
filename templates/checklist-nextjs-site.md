## 1. Старт и требования
- [ ] Цель сайта и главное целевое действие (заявка, звонок, покупка, запись)
- [ ] Карта страниц (sitemap) и структура меню согласованы
- [ ] Дизайн-макеты (Figma) для десктопа и мобильного, UI-кит (цвета, шрифты, кнопки, формы)
- [ ] Тексты, фото, логотип, фавикон получены от клиента
- [ ] Определено, кто будет менять контент: разработчик (контент в коде) или клиент (нужна CMS)
- [ ] Интеграции: CRM, почта, оплата, карты, мессенджеры, аналитика
- [ ] Языки сайта (мультиязычность нужна или нет)
- [ ] Домен и хостинг: чьи, куда деплоим, доступы получены

## 2. Настройка проекта
- [ ] `npx create-next-app@latest` — TypeScript, App Router, ESLint, `src/`-директория
- [ ] `tsconfig.json`: `"strict": true`, алиасы путей (`@/*`)
- [ ] Prettier + ESLint, форматирование при сохранении
- [ ] Стили выбраны: Tailwind CSS / CSS Modules
- [ ] Структура папок: `app/`, `components/`, `lib/`, `types/`, `public/`
- [ ] Git-репозиторий, `.gitignore` (`.env*`, `.next`, `node_modules`)
- [ ] `.env.example` со списком переменных (без значений); секреты только в `.env.local` и в настройках хостинга
- [ ] Зафиксирована версия Node.js (`.nvmrc` / `engines` в `package.json`)
- [ ] Husky + lint-staged (проверка перед коммитом) — по желанию

## 3. Вёрстка и компоненты
- [ ] Общий `layout.tsx`: шапка, подвал, навигация
- [ ] Шрифты через `next/font` (без запросов к Google Fonts в рантайме)
- [ ] Картинки через `next/image` с `width/height` или `fill` + `sizes`
- [ ] Адаптив: 360, 768, 1024, 1440+ px
- [ ] Мобильное меню, липкая шапка, якоря — работают
- [ ] Серверные компоненты по умолчанию, `"use client"` только где нужна интерактивность
- [ ] Состояния: загрузка (`loading.tsx`), ошибки (`error.tsx`), 404 (`not-found.tsx`)
- [ ] Типы для данных и пропсов описаны, нет `any`

## 4. Контент / CMS (если нужна)
- [ ] Выбрана CMS: Sanity / Strapi / Payload / Directus / Markdown/MDX в репозитории
- [ ] Схемы контента (страницы, услуги, статьи, отзывы) созданы
- [ ] Стратегия обновления: SSG + revalidate (ISR) / вебхук на revalidate при публикации
- [ ] Превью черновиков (Draft Mode) — если нужно клиенту
- [ ] Клиенту созданы доступы и показано, как редактировать

## 5. Формы и заявки
- [ ] Обработка через Server Actions или Route Handler (`app/api/.../route.ts`)
- [ ] Валидация на сервере (zod) + подсказки на клиенте
- [ ] Маска телефона, обязательные поля
- [ ] Защита от спама: honeypot-поле, rate limit, капча (Turnstile / reCAPTCHA / SmartCaptcha)
- [ ] Отправка заявки: на почту (SMTP/Resend) и/или в CRM (вебхук Битрикс24/amoCRM) и/или в Telegram
- [ ] UTM-метки сохраняются (cookie/localStorage) и передаются вместе с заявкой
- [ ] Галочка согласия на обработку персональных данных + ссылка на политику
- [ ] Понятное сообщение об успехе и об ошибке; страница «Спасибо» для целей аналитики
- [ ] Если отправка упала — заявка не теряется (лог / резервная отправка)

## 6. SEO
- [ ] `metadata` / `generateMetadata`: уникальные `title` и `description` на каждой странице
- [ ] Open Graph и Twitter-карточки, OG-картинка (`opengraph-image.tsx` или статичная)
- [ ] `app/sitemap.ts` и `app/robots.ts`
- [ ] `canonical` на всех страницах, один вариант домена (с www или без) — редирект со второго
- [ ] ЧПУ-адреса, редиректы со старых URL (`redirects` в `next.config`), если сайт переезжает
- [ ] Один `<h1>` на странице, правильная иерархия заголовков
- [ ] `alt` у всех значимых картинок
- [ ] Микроразметка JSON-LD (Organization, LocalBusiness, Product, BreadcrumbList, FAQ)
- [ ] Фавиконки: `app/icon.png`, `apple-icon.png`, `manifest`
- [ ] `lang` у `<html>`, `hreflang` для мультиязычности

## 7. Производительность
- [ ] Lighthouse (мобильный): Performance / Accessibility / Best Practices / SEO ≥ 90
- [ ] Core Web Vitals: LCP < 2.5 c, CLS < 0.1, INP < 200 мс
- [ ] Главная картинка первого экрана с `priority`
- [ ] Статические страницы собираются статически (проверить вывод `next build`)
- [ ] Тяжёлые компоненты — `dynamic()` импорт; сторонние скрипты через `next/script` с правильной стратегией
- [ ] Размер бандла проверен (`@next/bundle-analyzer`)
- [ ] Картинки сжаты, видео не грузятся на мобильном без нужды

## 8. Доступность
- [ ] Всё работает с клавиатуры, виден фокус
- [ ] Контраст текста достаточный
- [ ] У полей форм есть `label`, у иконок-кнопок — `aria-label`
- [ ] Семантичная разметка: `header`, `nav`, `main`, `footer`, `button` (а не `div` с onClick)

## 9. Безопасность
- [ ] Секреты не в `NEXT_PUBLIC_*` и не в клиентском коде
- [ ] Заголовки безопасности в `next.config` / middleware: CSP, X-Frame-Options, Referrer-Policy, HSTS
- [ ] Rate limit на API и формы
- [ ] `npm audit`, зависимости актуальные, Next.js на последней патч-версии
- [ ] Админка/CMS закрыта паролем, у клиента отдельный аккаунт
- [ ] Никаких тестовых данных, ключей и `console.log` с персональными данными

## 10. Аналитика и юридическое
- [ ] Яндекс Метрика (вебвизор, цели на формы/клики по телефону и мессенджерам) / Google Analytics 4
- [ ] Цели проверены в режиме отладки
- [ ] Яндекс Вебмастер и Google Search Console подключены, sitemap отправлен
- [ ] Политика конфиденциальности и согласие на обработку ПД (152-ФЗ в РФ / закон о персональных данных РК)
- [ ] Cookie-баннер, если используются аналитические cookie
- [ ] Реквизиты / контакты компании в подвале

## 11. Ошибки и мониторинг
- [ ] Sentry (или аналог) для ошибок клиента и сервера
- [ ] Мониторинг доступности (UptimeRobot / Uptime Kuma) + уведомление в Telegram
- [ ] Логи сервера доступны

## 12. Тестирование
- [ ] `tsc --noEmit` и `next lint` без ошибок
- [ ] `next build` проходит локально
- [ ] Unit-тесты для логики (Vitest / Jest) — где есть бизнес-логика
- [ ] E2E на ключевые сценарии (Playwright): открыть главную, отправить форму, навигация
- [ ] Ручная проверка: Chrome, Safari (включая iPhone), Firefox, Android
- [ ] Все ссылки рабочие, нет 404, телефоны кликабельные (`tel:`), почта (`mailto:`)
- [ ] Форма проверена «вживую» — заявка дошла по всем каналам
- [ ] Клиент прошёл сайт и согласовал правки

- [ ] Хостинг выбран: Vercel / Netlify / VPS (Docker, `output: "standalone"`, Nginx, PM2) / российский хостинг при требованиях к хранению ПД

- [ ] Переменные окружения заведены на продакшене
