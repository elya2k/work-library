# Cron и агенты в коробочном Битрикс24

Касается только коробки. В облаке это делает сам Битрикс24.

## Что это
**Агенты** — фоновые задачи Битрикса: синхронизация почты, отправка писем, отложенные
роботы и бизнес-процессы, напоминания, уведомления, регулярные задачи, очистка, индексация,
бэкапы.

Запускаться они могут двумя способами:
- **на хитах** (по умолчанию) — когда кто-то открывает страницу портала. Ночью или при малом
  числе пользователей агенты стоят, а днём замедляют загрузку страниц;
- **на cron** — системный планировщик Linux раз в минуту запускает
  `bitrix/modules/main/tools/cron_events.php`, и агенты выполняются независимо от посетителей.

Для портала нужен cron. Без него типичные симптомы: почта приходит с задержкой или пачками,
роботы с задержкой «через N минут» срабатывают когда попало, письма из портала уходят
поздно, напоминания не приходят.

## Как проверить
1. **Проверка системы**: Настройки → Инструменты → Проверка системы
   (`/bitrix/admin/site_checker.php`) → «Начать тестирование». Там есть пункт про выполнение
   агентов на cron — ошибка значит, что cron не настроен или не запускается.
2. **Список агентов**: Настройки → Настройки продукта → Агенты (`/bitrix/admin/agent_list.php`).
   Смотреть «Дата последнего запуска» и «Дата следующего запуска». Если у многих агентов
   следующий запуск давно в прошлом — агенты не выполняются.
3. **На сервере** (SSH):
   - `crontab -l -u bitrix` (на BitrixVM; иначе пользователь веб-сервера) — должна быть строка
     вида `* * * * * php -f /home/bitrix/www/bitrix/modules/main/tools/cron_events.php`;
   - `grep BX_CRONTAB_SUPPORT /home/bitrix/www/bitrix/php_interface/dbconn.php` —
     должно быть `define("BX_CRONTAB_SUPPORT", true);`;
   - запустить вручную `php -f .../cron_events.php` — если падает с ошибкой, cron тоже падает;
   - лог cron: `grep CRON /var/log/cron` или `/var/log/syslog`.

## Как включить (кратко)
1. В `dbconn.php`: `define("BX_CRONTAB_SUPPORT", true);`
2. В crontab пользователя веб-сервера: запуск `cron_events.php` каждую минуту.
3. Агенты на хитах при этом отключаются (опции главного модуля `agents_use_crontab` и
   `check_agents`), чтобы не выполнялись дважды.
4. Через несколько минут проверить список агентов и «Проверку системы».

На BitrixVM cron обычно уже настроен при установке — если сломался, проверять crontab
пользователя `bitrix` и путь к сайту.
