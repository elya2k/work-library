# ChatApp в Битрикс24: «Ошибка получения токена авторизации»

Симптом: приложение ChatApp в Битрикс24 (`/devops/placement/<id>/` или пункт меню ChatApp) открывается с красным значком и текстом «Ошибка получения токена авторизации».

Значит, сервер ChatApp не может получить или обновить OAuth-токен портала: связка «портал ↔ ChatApp» разорвана. Сами каналы при этом могут быть живы.

## Проверка по порядку (от частых причин к редким)

1. **Ctrl+F5 / другой браузер / инкогнито**, отключить блокировщики рекламы и VPN. Если проблема у одного пользователя, а у админа всё открывается — это права или кэш.
2. **Открыть приложение под администратором портала** — желательно под тем, кто ставил ChatApp. Если этот сотрудник уволен или деактивирован, токен, выданный на него, перестаёт работать: открыть под другим админом или переустановить.
3. **Переавторизация в личном кабинете ChatApp**: Интеграции → Битрикс24 → «Переподключить» / «Авторизоваться заново». Refresh-токен Битрикса живёт ограниченное время (около 28 дней); если интеграция долго не обращалась к порталу, токен «протухает».
4. **Оплата / подписка ChatApp**: проверить, что тариф ChatApp не закончился.
5. **Переустановка приложения**: Приложения → Мои приложения (или Маркет) → ChatApp → Переустановить. Удалять не обязательно; при удалении могут потеряться настройки линий.

### Только для коробки (свой домен, например `crm.company.kz`)

6. **Лицензия Битрикс24 активна** (Настройки → Обновления платформы / Лицензия). С истёкшей лицензией или без регистрации портала в сети Битрикс24 OAuth-токены для приложений Маркета не выдаются.
7. **Портал доступен из интернета по HTTPS** с валидным сертификатом (не самоподписанный, не истёкший, полная цепочка). Сервер ChatApp должен «достучаться» до портала. Проверить сайт через SSL-checker.
8. **Сервер портала сам ходит наружу**: из консоли сервера `curl -I https://oauth.bitrix.info` и `curl -I https://<сервер ChatApp>` — не режет ли фаервол или провайдер.
9. **Время на сервере правильное** (NTP). Большое расхождение ломает OAuth.
10. **Проверка системы** (Настройки → Инструменты → Проверка системы) → пункт про REST/OAuth, плюс модуль `rest` обновлён.
11. В настройках главного модуля указан **правильный URL сайта** с `https://` (с ним ходят коллбэки).

## Если ничего не помогло

Написать в поддержку ChatApp: адрес портала, скриншот, время ошибки, облако или коробка. Они видят в логах, какой ответ им вернул Битрикс (`invalid_grant`, `expired_token`, `wrong_client`, таймаут и т.п.), и это сразу указывает на причину.
