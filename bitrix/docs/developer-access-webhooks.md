# Доступ разработчику в Битрикс24 (вебхуки, приложения, REST)

> Названия пунктов меню отличаются в разных версиях интерфейса и между облаком и коробкой. Логика везде одна.

## Главное, что надо понимать

- Вебхук работает **с правами того пользователя, который его создал**. Если у него нет доступа к сделкам, вебхук тоже не увидит сделки.
- По умолчанию **входящие вебхуки и свои локальные приложения могут создавать все пользователи**, приложения для всех пользователей — только администратор. Администратор может сузить или поменять эти права (вариант 2).
- Поэтому есть три рабочих варианта.

## Вариант 1 (рекомендуется). Технический пользователь «Интеграция»

Отдельная учётка, через которую работают все интеграции. Разработчик не получает доступ к вашему личному аккаунту, а при увольнении подрядчика ничего не ломается.

1. **Сотрудники → Пригласить** → создать пользователя, например `integration@ваш-домен` (имя «Интеграция»).
   Учтите: он занимает одно место в лимите пользователей тарифа.
2. Дать ему права администратора:
   **Настройки → Права доступа / Администраторы → Добавить** (в старом интерфейсе: профиль сотрудника → «Сделать администратором»).
   На младших тарифах число администраторов ограничено — проверьте лимит своего тарифа.
3. Если админ не нужен, хватит прав на нужные модули:
   - CRM: **CRM → Настройки → Права доступа → Роли** → создать роль «Интеграция» (чтение/запись по нужным сущностям) и назначить её пользователю;
   - задачи, диск, бизнес-процессы — права в соответствующих разделах.
4. Залогиниться под этой учёткой (или пусть разработчик залогинится) и создать вебхук, как описано ниже.
5. Включить двухфакторную авторизацию для этой учётки.

## Вариант 2. Выдать права на вебхуки конкретному сотруднику

Делает администратор:

1. Значок настроек справа от названия/логотипа портала → **Настройки**.
2. Вкладка **Безопасность** → блок **Интеграции Битрикс24**.
3. Проверить блок **Вайбкод-коннектор**: если включён тумблер **«Источник прав — Вайбкод-сервер»**, действуют права из Битрикс24 Вайбкод, а настройки ниже не применяются. Чтобы они сработали — выключить тумблер.
   На практике, пока тумблер включён, поля выбора сотрудников могут вообще не показываться: в блоке виден только тумблер, а сразу под ним идёт «История входов». Поля появляются после выключения тумблера (если нет — сохранить настройки и обновить страницу). Альтернатива — оставить тумблер и настроить права на самом Вайбкод-сервере.
4. В каждом поле нажать **+ Добавить** и выбрать сотрудников, которые смогут создавать вебхуки и приложения.
5. Сохранить.
6. Проверить, что у сотрудника есть права на сами данные (роль в CRM и т. д.) — иначе вебхук будет получать пустые ответы или `ACCESS_DENIED`.

### Где настраиваются права на Вайбкод-сервере

Вайбкод-сервер — это не пункт меню портала, а отдельный сервис Битрикс24 Вайбкод: https://vibecode.bitrix24.tech
1. Открыть сайт → войти через Битрикс24 → выбрать свой портал (под администратором портала).
2. В кабинете администратор отдельно настраивает: **доступ в кабинет (вход)** и **право создавать ключи, серверы, ботов**, а также лимиты на сотрудника.
3. Добавить разработчика в обе настройки — после этого он создаёт ключи в кабинете Вайбкода.

Точные названия пунктов в кабинете не сверены. Документация: https://vibecode.bitrix24.tech/docs, https://helpdesk.bitrix24.ru/open/28436840/

## Вариант 3. Пригласить разработчика как «Специалиста по внедрению» (облако)

Отдельная роль для интеграторов (раньше пункт назывался «Интегратор»), см. `invite-integrator.md`:

1. Открыть портал в браузере на компьютере (в мобильном приложении функции нет).
2. Вверху кнопка **Пригласить** → в окне ещё раз **Пригласить** → слева выбрать **Специалист по внедрению**.
3. Ввести почту разработчика → **Пригласить**.

Права почти как у администратора, отдельно назначать админом не нужно; при этом он не может менять администраторов и отключать защиту входа сотрудникам. После окончания работ — удалить из портала.
Если кнопка «Пригласить» неактивна — приглашать может только админ (или включить «Разрешить всем приглашать пользователей» в Настройках → Сотрудники).

## Коробка (1С-Битрикс: Корпоративный портал)

- Админ-панель: **Настройки → Пользователи → Группы пользователей** → добавить разработчика в группу «Администраторы» (или в отдельную группу).
- Права на модуль REST: **Настройки → Настройки продукта → Настройки модулей → REST API** → вкладка «Доступ» → дать группе разработчика нужный уровень.
- Если нужен доступ к файлам/SSH/БД — отдельно, на уровне сервера, не через портал.

## Как создать вебхук (после выдачи прав)

1. **Приложения → Разработчикам → Другое** (или вкладка «Готовые сценарии»).
2. **Входящий вебхук** — когда внешняя система вызывает Битрикс24:
   - отметить нужные права (scope): `crm`, `task`, `user`, `disk`, `im` и т. д. — **только необходимые**;
   - сохранить, скопировать URL вида `https://портал.bitrix24.ru/rest/<ID_пользователя>/<ключ>/`.
3. **Исходящий вебхук** — когда Битрикс24 сам шлёт событие во внешнюю систему:
   - указать URL обработчика;
   - выбрать события (`ONCRMDEALADD`, `ONCRMLEADUPDATE` и т. п.);
   - сохранить токен приложения — по нему обработчик проверяет, что запрос действительно от портала.
4. Для сложных интеграций (свой интерфейс, установка на портал, OAuth) — **Локальное приложение** в том же разделе.

## Безопасность

- URL входящего вебхука = логин + пароль. Не отправлять в открытых чатах, не коммитить в репозиторий, хранить в менеджере паролей / `.env`.
- Минимум scope'ов на вебхук; на каждую интеграцию — свой вебхук, чтобы можно было отозвать один, не трогая остальные.
- После окончания работ: снять у подрядчика права администратора / отключить пользователя, перевыпустить ключи вебхуков (кнопка «Сгенерировать новый ключ» или удалить и создать заново).
- Вебхук перестаёт работать, если пользователь-владелец уволен/деактивирован — ещё одна причина использовать техническую учётку.

## Типовые проблемы

| Симптом | Причина / решение |
|---|---|
| Нет раздела «Разработчикам» / нельзя создать вебхук | Администратор ограничил права в Настройки → Безопасность → Интеграции Битрикс24 (вариант 2), либо включён источник прав «Вайбкод-сервер» |
| `insufficient_scope` | У вебхука не отмечен нужный scope — отредактировать вебхук |
| `ACCESS_DENIED` / пустой список | У пользователя-владельца нет прав на данные (роль CRM) |
| `Invalid request credentials` / 401 | Ключ перевыпущен, пользователь деактивирован или URL скопирован не полностью |
| Нельзя добавить администратора | Достигнут лимит администраторов на тарифе |
