# CRM: дата создания с часами и минутами (список и канбан)

Симптом: в сделках вместо точного времени создания видно «сегодня», «вчера»
или просто «1 октября» — без часов и минут.

## Что известно точно
- Поле `DATE_CREATE` хранит дату **и время** создания — данные есть, вопрос только в отображении.
- Шестерёнка (⚙️) в левом верхнем углу таблицы в режиме «Список» отвечает за набор
  колонок. Отдельного переключателя «показывать время / относительные даты» там
  **не найдено** (проверено пользователем, октябрь 2026). Не обещать клиенту такую настройку.
- Формат даты/времени портала задаётся в региональных настройках (администратор).
  Он влияет на полный формат, но не отключает «сегодня/вчера» в CRM.

## Рабочий способ (список и канбан): своё поле «Дата/время»
1. CRM → Сделки → Настройки → Пользовательские поля → создать поле типа
   «Дата/время», например «Создана (время)».
2. Роботы → первая стадия каждой воронки → «Изменить элемент» →
   «Создана (время)» = `{{Дата создания}}`. Робот сработает при создании сделки.
3. Список: ⚙️ → включить колонку «Создана (время)».
   Канбан: «Настроить вид карточки» → вывести это поле.
4. Старые сделки заполнить массово: бизнес-процесс по выборке или REST
   `crm.deal.update` (`UF_CRM_...` = значение `DATE_CREATE` из `crm.deal.list`).

## Нюансы
- Роботы доступны не на всех тарифах (на бесплатном ограничены) — проверить тариф.
- Робот ставить на первую стадию **каждой** воронки, иначе сделки из других воронок
  останутся без времени. Если сделки создаются сразу на другой стадии
  (интеграции, конвертация лида) — робот «на входе в стадию» там тоже нужен.
- Тип поля именно «Дата/время», а не «Дата» — иначе время обрежется.
- Быстрый просмотр без настроек: экспорт списка в Excel — дата создания обычно
  выгружается вместе со временем.
