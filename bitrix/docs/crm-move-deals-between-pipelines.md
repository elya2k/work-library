# CRM: перенос сделок между воронками

Да, сделку можно перенести в другую воронку. Есть четыре способа: вручную,
массово из списка, автоматически роботом и через REST API.
Раньше воронки назывались «направления», поэтому в старых интерфейсах
и в API пункт может называться «Сменить направление».

## 1. Одна сделка — вручную
1. Открыть карточку сделки.
2. Вверху, рядом с названием, нажать на название текущей воронки.
3. Выбрать нужную воронку.
4. Сделка встанет на первую стадию новой воронки (в новых версиях можно сразу выбрать стадию).
   Потом при необходимости передвинуть её на нужную стадию.

## 2. Много сделок сразу — из списка
1. CRM → Сделки → переключиться на вид **«Список»** (в канбане массовых действий нет).
2. Выбрать нужную воронку и отфильтровать сделки (по стадии, ответственному и т. п.).
3. Отметить сделки галочками (или «Для всех»).
4. Внизу на панели действий выбрать **«Сменить воронку»** (может быть в «Ещё»)
   → указать воронку → «Применить».

## 3. Автоматически — робот
Подходит, когда воронки идут по цепочке. Например, сделка выиграна в «Продажах»
и дальше должна попасть в «Производство» или «Доставку».
1. Сделки → нужная воронка → «Роботы».
2. На стадии, с которой нужен перенос, добавить робота **«Сменить воронку»**
   («Изменить направление» в старых версиях) и указать целевую воронку.
3. Альтернатива: робот **«Создать копию сделки»** в другой воронке.
   Исходная сделка останется на месте, а в новой воронке появится копия.
   Это удобно, когда нужна отдельная статистика по каждой воронке.
- Роботы доступны не на всех тарифах облака — проверить в текущем тарифе.
- Сложную логику с условиями можно собрать в бизнес-процессе.

## 4. Через REST API
- Воронки: `crm.category.list` с `entityTypeId: 2` (сделки) → ID воронок.
- Стадии воронки: `crm.status.list`, фильтр `ENTITY_ID = DEAL_STAGE_<ID воронки>`
  (у основной воронки — `DEAL_STAGE`). Стадии не основной воронки имеют вид `C<ID>:NEW`.
- `crm.deal.update` **не меняет** `CATEGORY_ID`: поле при обновлении игнорируется.
- Для переноса использовать `crm.item.update`:
  ```json
  {
    "entityTypeId": 2,
    "id": 123,
    "fields": { "categoryId": 5, "stageId": "C5:NEW" }
  }
  ```
  Сначала проверить на одной тестовой сделке.

## Что важно знать
- **Сохраняется:** история, дела, комментарии, файлы, контакт и компания, товары.
- **Права доступа** настраиваются отдельно для каждой воронки. Перенести сделку
  может только тот, у кого есть права на целевую воронку. После переноса сделку
  могут перестать видеть сотрудники без доступа к новой воронке.
- **Роботы и бизнес-процессы** на стадии новой воронки запустятся при переносе.
  Проверить, что они не отправят клиенту лишние SMS или письма.
- **Поля:** пользовательские поля сделок общие для всех воронок, но в разных
  воронках можно скрыть разные поля в карточке. Значения при переносе не теряются.
- **Отчёты и аналитика** считают сделку уже по новой воронке.
  Если нужна статистика в обеих воронках, лучше делать копию сделки (робот).
