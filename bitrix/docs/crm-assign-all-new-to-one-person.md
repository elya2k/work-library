# CRM: все новые заявки — на одного сотрудника

## Способ 1 (универсальный): робот на первой стадии
CRM → Сделки → Роботы → нужная воронка → первая стадия →
«Добавить» → «Сотрудники» (или «Ответственный») → **«Сменить ответственного»**
→ выбрать сотрудника → запуск «сразу» → Сохранить.

Ловит заявки из любого источника (формы, звонки, чаты, почта, интеграции, ручное создание).

Нюансы:
- Несколько воронок → робот в каждой.
- Если сделки создаются сразу не на первой стадии (интеграции, конвертация лида) —
  робот и на той стадии тоже.
- Работаете с лидами (классический режим CRM) — такой же робот в **Лидах**,
  на стадии «Не обработан».
- Чтобы менять ответственного только у новых, а не при каждом возврате на стадию —
  условие робота, например «Ответственный ≠ нужный сотрудник».
- Если в роботе выбрать несколько сотрудников, появляется распределение
  (по очереди / случайно) — для одного человека не нужно.

## Способ 2: в самих источниках (чтобы сразу создавалось на нём)
- CRM-формы → настройки формы → ответственный / очередь.
- Открытые линии → настройки линии → очередь.
- Телефония → настройки номера → ответственный / очередь.
- Почта → CRM-интеграция ящика → ответственный.
- Интеграции/вебхуки → `ASSIGNED_BY_ID` в коде.
Полный список мест — `deleted-employee-still-gets-leads.md`.

Рекомендация: способ 1 как страховка + способ 2 в основных источниках.
Повторные обращения старых клиентов могут уходить на «их» ответственного —
робот это перебьёт.

## Разбор: «Ответственный» поменялся везде, а своё поле «Менеджер ОП» — частично
Симптом: робот меняет ответственного и пользовательское поле «Менеджер ОП» на нового
менеджера. Ответственный новый везде, а в «Менеджер ОП» у части сделок старый.

Причины (по частоте):
1. **Роботы не работают задним числом.** Робот срабатывает только при попадании сделки на
   стадию после его сохранения. Новое значение получили только сделки, прошедшие через
   стадию; остальные остались со старым. (Ответственный часто меняют массово в списке —
   «Назначить ответственного», поэтому он новый везде.)
2. **Робот стоит не на всех стадиях / не во всех воронках.**
3. **Поле заполняется как `{{Ответственный}}`**, и этот робот выполнился раньше
   «Сменить ответственного» → в поле записался старый ответственный. Лечится: в поле
   указать конкретного сотрудника, а не подстановку, или запускать после предыдущего робота.
4. **Поле перезаписывает кто-то ещё:** другой робот, бизнес-процесс, конвертация лида
   (поле переносится из лида), интеграция.
5. **Условие робота** не выполнилось у части сделок, или робот упал с ошибкой.

Как проверить на одной «плохой» сделке:
- карточка → вкладка «История» → изменения поля «Менеджер ОП»: кто/что и когда менял;
- лента сделки — записи о выполнении роботов/ошибки;
- в настройках роботов: на каких стадиях/воронках стоит, условия, порядок запуска.

Исправить старые сделки:
- немного — список → фильтр «Менеджер ОП = старый» → отметить → «Редактировать» в
  нижней панели → поменять в ячейках → «Сохранить»;
- много — REST: `crm.deal.list` с фильтром `UF_CRM_...` = ID старого →
  `crm.deal.update` пачкой (batch).

## Массово заменить уволенного сотрудника в поле «Менеджер ОП»
Скрипт: `bitrix/snippets/reassign-deal-user-field.js` (запуск в консоли браузера).
1. Вебхук: Приложения → Разработчикам → Другое → Входящий вебхук → права CRM.
2. ID сотрудников: открыть профиль, число в ссылке `/company/personal/user/123/`.
   Уволенного найти в Сотрудниках с фильтром «Уволенные» или кликнуть по имени в сделке.
3. Вставить в скрипт вебхук и оба ID, запустить с `DRY_RUN = true` → увидеть количество.
4. `DRY_RUN = false` → запустить ещё раз. Вебхук после работы удалить.
Чтобы новые сделки снова не получали уволенного — проверить в настройках поля
«Значение по умолчанию» и роботов/БП, которые заполняют это поле.
