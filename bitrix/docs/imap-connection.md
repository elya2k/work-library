# Подключение почтового ящика по IMAP к Битрикс24

> Названия пунктов меню немного отличаются в разных версиях интерфейса и между облаком и коробкой. Логика везде одна.

## 0. Что нужно подготовить заранее

| Что | Где взять |
|---|---|
| Адрес ящика (полностью, `user@domain.ru`) | — |
| Пароль **приложения** (не основной пароль) | В настройках безопасности почтового сервиса |
| IMAP-сервер, порт, шифрование | У почтового провайдера / админа почты |
| SMTP-сервер, порт, шифрование (для отправки) | Там же |
| Включённый доступ по IMAP в самом ящике | В настройках ящика |
| Права в Битрикс24 на подключение почты | Администратор портала |

### Типовые параметры

| Провайдер | IMAP | SMTP | Особенности |
|---|---|---|---|
| Яндекс (и Яндекс 360) | `imap.yandex.ru:993` SSL | `smtp.yandex.ru:465` SSL | Настройки → Почтовые программы → включить IMAP, способ авторизации «Пароли приложений и OAuth-токены»; создать пароль приложения в Яндекс ID → Безопасность |
| Mail.ru | `imap.mail.ru:993` SSL | `smtp.mail.ru:465` SSL | Пароль для внешнего приложения (Безопасность → Пароли для внешних приложений), тип доступа IMAP/SMTP |
| Gmail / Google Workspace | `imap.gmail.com:993` SSL | `smtp.gmail.com:465` SSL | Лучше выбрать плитку Gmail в Битрикс24 (вход через OAuth). По логину/паролю — только пароль приложения, требует 2FA |
| Microsoft 365 / Outlook.com | `outlook.office365.com:993` SSL | `smtp.office365.com:587` STARTTLS | Обычная авторизация по паролю отключена Microsoft — использовать плитку Office 365 / Outlook (OAuth) |
| Свой сервер / хостинг | обычно `mail.domain.ru:993` SSL | `mail.domain.ru:465` SSL или `587` STARTTLS | Уточнить у хостера; проверить, что сервер не блокирует внешние IP |

Порт 143 (без шифрования / STARTTLS) использовать только если 993 недоступен.

## 1. Подготовка почтового ящика

1. Войти в ящик через веб-интерфейс.
2. Включить IMAP в настройках.
3. Включить двухфакторную аутентификацию (для Gmail обязательно для паролей приложений).
4. Создать пароль приложения, назвать его «Bitrix24», сохранить (показывается один раз).
5. Для корпоративной почты: попросить админа разрешить IMAP-подключения с внешних IP (облако Битрикс24 ходит со своих серверов, часто зарубежных — их могут резать фаервол, fail2ban или гео-блокировки).

## 2. Подключение в Битрикс24

1. Левое меню → **Почта** (или «Мессенджер/Коллабы → Почта», в CRM — «Добавить почтовый ящик»).
2. Выбрать провайдера плиткой. Если его нет — **«Другая» / IMAP**.
3. Заполнить:
   - **E-mail** — полный адрес;
   - **IMAP-сервер**, **порт** (993), галка **SSL**;
   - **Логин** — как правило полный адрес;
   - **Пароль** — пароль приложения.
4. **Название ящика** — как он будет отображаться в Битриксе.
5. **Период загрузки писем** при первой синхронизации (день/неделя/месяц/…). На больших ящиках не брать максимум — первичная загрузка будет идти очень долго.
6. **Отправка (SMTP)** — включить «Использовать внешний SMTP» и указать сервер/порт/пароль. Если не включить, письма уйдут через серверы Битрикс24 от имени вашего домена → риск попадания в спам (SPF/DKIM не совпадут).
7. **Папки**: выбрать какие папки синхронизировать и сопоставить служебные — «Отправленные», «Спам», «Корзина». Если не указать папку «Отправленные», письма, отправленные из Битрикса, не появятся в ящике и наоборот.
8. **Доступ**: кому ещё из сотрудников дать доступ к ящику (общий ящик отдела продаж/поддержки).
9. Нажать **«Подключить»**. Первая синхронизация — от минут до часов.

## 3. Интеграция с CRM (самое важное для продаж)

В настройках ящика блок «Интеграция с CRM»:

- **Обрабатывать входящие / исходящие** — какие письма привязывать к CRM.
- **Создавать для новых адресов**: лид / контакт / сделку (зависит от режима CRM: классический с лидами или простой без лидов).
- **Источник** создаваемых лидов (например «E-mail»), чтобы потом видеть в аналитике.
- **Ответственные / очередь распределения** — между кем по очереди распределять новые лиды.
- **Обрабатывать письма за последние N дней** при подключении — осторожно: на старом ящике это наплодит сотни лидов.
- **Список исключений** — адреса и домены, из которых НЕ создавать лиды (рассылки, уведомления сервисов, `noreply@`, свои же сотрудники, бухгалтерия банков и т.п.). Заполнить сразу.
- Письма от уже существующих контактов/компаний привязываются к ним автоматически (по e-mail в карточке).

## 4. Проверка

1. Отправить на ящик письмо с постороннего адреса → оно появилось в «Почте» (обычно в течение нескольких минут) → создался лид/контакт по правилам.
2. Ответить из Битрикса → письмо дошло, лежит в «Отправленных» ящика, не попало в спам у получателя.
3. Проверить заголовки полученного письма: `SPF: pass`, `DKIM: pass`.

## 5. Нюансы и типичные ошибки

| Симптом | Причина / решение |
|---|---|
| «Ошибка авторизации» | Указан основной пароль вместо пароля приложения; IMAP выключен; у Яндекса не выбран способ входа «пароли приложений»; у Microsoft/Google базовая авторизация запрещена → использовать OAuth-плитку |
| «Не удалось подключиться к серверу» | Неверный хост/порт/SSL; фаервол почтового сервера блокирует IP Битрикс24; самоподписанный или просроченный SSL-сертификат |
| Письма приходят с задержкой | Облако проверяет ящик периодически, это не мгновенно; в коробке — не настроен cron для агентов |
| Письма уходят в спам | Отправка не через внешний SMTP; нет SPF/DKIM/DMARC у домена |
| Дубли лидов | Включена обработка старых писем; не заполнен список исключений; один ящик подключён дважды разными сотрудниками |
| Нет «Отправленных» | Не сопоставлена папка отправленных (особенно если она называется по-русски или `INBOX.Sent`) |
| Перестало работать через время | Сменили пароль ящика / отозвали пароль приложения / уволенный сотрудник был владельцем ящика — переподключить |
| Ограничение на количество ящиков | Зависит от тарифа Битрикс24 — проверить условия текущего тарифа |

## 6. Особенности коробочной версии

- Нужен модуль **«Почта» (mail)**.
- Сервер должен иметь исходящий доступ на порты 993/465/587 (проверка: `openssl s_client -connect imap.yandex.ru:993`).
- PHP с поддержкой OpenSSL.
- Агенты синхронизации должны выполняться на **cron**, а не на хитах, иначе почта будет «застревать»: `define("BX_CRONTAB_SUPPORT", true);` в `dbconn.php` и задание cron на `bitrix/modules/main/tools/cron_events.php` раз в минуту.
- Отправка системных писем самого портала настраивается отдельно (SMTP в настройках главного модуля / `.settings.php`) — это не то же самое, что SMTP подключённого ящика.

## 7. Безопасность

- Только пароли приложений, никогда основной пароль.
- При увольнении сотрудника: отключить ящик в Битриксе и отозвать пароль приложения.
- Общие ящики (sales@, info@) подключать от служебной учётки, а не от личной, и выдавать доступ сотрудникам через настройки ящика.
- Пароли и токены не хранить в этом репозитории.
