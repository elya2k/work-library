# Удалили сотрудника, а на него продолжают падать заявки

Симптом: сотрудника уволили/удалили из Битрикс24, но новые лиды/сделки по-прежнему
назначаются на него ответственным. Заявки «висят» — уволенный не получает уведомлений
и никто их не обрабатывает.

Причина: удаление или увольнение пользователя в Битрикс24 **не меняет** настройки,
где прописан его ID. Везде, где он был указан ответственным «по умолчанию» или стоял
в очереди, его ID остаётся, и распределение продолжает работать на него.

## Где искать (чек-лист по источникам заявок)

Сначала открыть свежую заявку, попавшую на уволенного, и посмотреть поле **Источник** —
оно подскажет, какой канал назначает ответственного.

1. **CRM-формы**: CRM → Интеграции (или Сайты/Формы) → CRM-формы → настройки каждой формы →
   «Ответственный» / очередь ответственных. Убрать уволенного из очереди.
2. **Открытые линии**: Контакт-центр → канал → настройки открытой линии → «Очередь» —
   удалить сотрудника из очереди (уволенные подсвечиваются, но из очереди сами не удаляются).
3. **Телефония**: Телефония → настройки номера → «Ответственный за обработку пропущенного
   звонка» и очередь распределения звонков.
4. **Почта**: CRM-интеграция почтового ящика — ответственный за лиды с писем.
   Если ящик был подключён лично уволенным — переподключить на другого.
5. **Роботы и триггеры**: CRM → Настройки → Роботы (в лидах и сделках) — роботы
   «Изменить ответственного» / «Поменять ответственного» могли назначать конкретного человека.
6. **Бизнес-процессы**: шаблоны БП, где ответственный задан жёстко или через «руководителя»
   уволенного.
7. **Повторные лиды/обращения**: если включён режим «повторный лид уходит ответственному
   за клиента», то заявки от старых клиентов уволенного будут падать на него, пока
   за ним числятся контакты/компании. Лечится только передачей его базы другому.
8. **Сторонние интеграции**: сайт, Tilda, Wazzup, коннекторы, самописные вебхуки —
   в коде интеграции часто жёстко прошит `ASSIGNED_BY_ID`. Проверить код/настройки
   интеграции на стороне сайта.
9. **Распределение прав/настройки CRM**: «ответственный по умолчанию» в настройках
   источников и обязательных полей.

## Передать существующие элементы CRM

Массово в интерфейсе: CRM → Лиды (и отдельно Сделки, Контакты, Компании) →
фильтр «Ответственный = уволенный» → выделить все → «Назначить ответственного».
Нужны права администратора CRM.

## Через REST (если элементов много)

Найти всё, что висит на пользователе (ID можно взять из URL профиля или `user.get`
с `ACTIVE = false`):

```
crm.lead.list?filter[ASSIGNED_BY_ID]=123&filter[STATUS_SEMANTIC_ID]=P
crm.deal.list?filter[ASSIGNED_BY_ID]=123&filter[CLOSED]=N
crm.contact.list?filter[ASSIGNED_BY_ID]=123
crm.company.list?filter[ASSIGNED_BY_ID]=123
```

Переназначить пачкой через `batch`:

```php
// вебхук-URL с ключом не хранить в репозитории
$result = CRest::call('crm.lead.update', [
    'id' => $leadId,
    'fields' => ['ASSIGNED_BY_ID' => $newUserId],
]);
```

## Нюансы

- В Битрикс24 (облако) пользователь обычно не «удаляется», а **увольняется** —
  его ID продолжает существовать, поэтому назначение на него технически проходит
  без ошибок, просто заявки никто не видит.
- Правильный порядок при увольнении: сначала убрать из всех очередей и настроек,
  передать элементы CRM, и только потом увольнять.
- После исправления настроек создать тестовую заявку по каждому каналу
  (форма, звонок, чат, почта) и проверить, на кого она упала.
