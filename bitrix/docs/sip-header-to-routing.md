# Параметр «Обработка SIP-заголовка TO» (маршрутизация входящих звонков)

Где: Телефония → Настройки линии (SIP-коннектор / офисная или облачная АТС) →
«Маршрутизация входящих звонков» → «Обработка SIP-заголовка TO».

## Что делает
Когда на линию приходит входящий звонок, АТС/оператор шлёт в Битрикс24 SIP-запрос `INVITE`.
В нём есть заголовок `To`, например:

```
To: <sip:105@pbx.example.ru>
```

При включённой галочке Битрикс24 берёт user-часть заголовка (`105`) и ищет сотрудника
с таким **внутренним номером** (Телефония → Пользователи / профиль сотрудника → «Внутренний номер»).
Нашёл — звонок сразу идёт этому сотруднику, минуя обычную схему линии
(очередь/группу, IVR, «ответственного за линию»).

Если такого внутреннего номера нет — звонок обрабатывается по обычным правилам линии.
Если галочка выключена — `To` игнорируется, все звонки идут по настройкам линии.

## Когда нужно
- Маршрутизацию делает своя АТС (Asterisk/FreePBX, облачная АТС оператора), а Б24 —
  только «телефон» сотрудников: АТС сама решает, кому звонок, и кладёт добавочный в `To`.
- У каждого сотрудника свой прямой номер (DID) — АТС переводит DID в добавочный и
  передаёт его в `To`.
- Звонок с добавочным, набранным в голосовом меню АТС.

## Нюансы
- Многие операторы кладут в `To` не добавочный, а сам номер (DID, `+7...`) или SIP-логин —
  тогда совпадения нет и опция ничего не меняет. Нужно настроить на стороне АТС/оператора,
  чтобы в `To` уходил внутренний номер (в Asterisk — подменой заголовка/диалом на `ext@...`).
- Внутренние номера в Б24 должны совпадать с добавочными на АТС.
- Сотрудник должен быть доступен (онлайн в приложении/браузере, SIP-телефон или
  переадресация на мобильный), иначе — по его настройкам недоступности/переадресации.
- Проверка: посмотреть SIP-лог на стороне АТС (`sip set debug on` в Asterisk) — что реально
  приходит в `To` при звонке.
