# Диск: «Unexpected server response» при загрузке видео

Симптом: Диск → «Добавить» → «Загрузить файл», в окне «Загрузка нового документа»
файл (обычно большое видео .mp4 с телефона) подсвечивается красным,
«Загружено файлов 0 из 1», ошибка `Unexpected server response`.

Смысл ошибки: загрузчик ждал от сервера JSON, а получил что-то другое
(страницу ошибки 413/502/504, пустой ответ, обрыв соединения). Конкретную причину
сообщение не называет — ищем перебором, от простого к сложному.

## 1. Быстрые проверки (облако и коробка)
1. **Размер файла.** Посмотреть, сколько весит видео. Если больше ~1–2 ГБ — первый подозреваемый.
2. **Место на диске портала.** Профиль/«Мой тариф» → объём диска. Если квота исчерпана
   или файл в неё не помещается — загрузка падает. Почистить корзину Диска
   (корзина тоже занимает место) или расширить тариф.
3. **Другой браузер / режим инкогнито.** Отключить блокировщики рекламы, VPN,
   расширения-«ускорители». Часто помогает сразу.
4. **Другая сеть.** Корпоративный прокси/антивирус (проверка HTTPS-трафика, Kaspersky,
   ESET и т. п.) и нестабильный Wi-Fi рвут длинные загрузки. Попробовать с раздачи
   телефона.
5. **Имя файла.** Переименовать в простое латиницей без пробелов (`video.mp4`).
6. **Перелогиниться.** Если страница была открыта давно, истекшая сессия даёт тот же
   «неожиданный ответ». Обновить страницу (Ctrl+F5) и загрузить снова.
7. **Другие способы загрузки:** перетащить файл мышкой прямо в папку;
   загрузить через приложение **Битрикс24.Диск** (десктоп) — оно грузит частями
   и докачивает; через мобильное приложение.
8. Проверить, грузятся ли **маленькие** файлы в эту же папку. Если тоже нет —
   проблема с правами на папку («Отдел продаж/…» — нужно право «Редактирование»)
   или с порталом, а не с размером.

## 2. Если коробка (свой сервер) — почти всегда лимиты сервера
Большие файлы упираются в настройки веб-сервера/PHP. Проверить и поднять:

- **nginx** (Битрикс ВМ: `/etc/nginx/bx/conf/` или `bx/settings/`):
  `client_max_body_size 1024m;` (или больше) → ошибка 413 до PHP не доходит.
  Также `proxy_read_timeout` / `send_timeout`, если файл гигантский.
- **PHP** (`php.ini` или `/etc/php.d/bitrixenv.ini`):
  `upload_max_filesize`, `post_max_size` (≥ upload_max_filesize),
  `max_execution_time`, `max_input_time`, `memory_limit`.
- **Временная папка** (`upload_tmp_dir` / `/tmp`) — хватает ли места на разделе.
  Свободное место на самом сервере (`df -h`) и на разделе с `/upload/`.
- **Настройки главного модуля** → «Максимальный размер загружаемого файла»
  и настройки модуля Диск — нет ли там лимита.
- **Квота** «Настройки продукта → Настройки модулей → Главный модуль → Дисковая квота».
- После правок — `systemctl reload nginx` / перезапуск php-fpm/httpd.
- Смотреть логи: `/var/log/nginx/error.log` (ищем `client intended to send too large body`,
  `upstream timed out`), лог PHP — там будет реальная причина.

Проверка в браузере: F12 → Network → повторить загрузку → кликнуть на красный
запрос → код ответа: **413** = лимит размера, **502/504** = таймаут/упал php-fpm,
**401/403** = сессия/права, **0 / failed** = обрыв сети/антивирус.

## 3. Если облако и ничего не помогло
- Тарифный лимит / квота — смотреть в «Мой тариф».
- Писать в техподдержку Битрикс24 (вопрос в разделе «Поддержка 24» или через партнёра):
  приложить имя и размер файла, время попытки, браузер, скрин вкладки Network (F12).

## Обходные пути, пока не починили
- Сжать видео (HandBrake, или отправить себе в Telegram/WhatsApp и скачать — сожмётся).
- Загрузить через десктопное приложение Битрикс24.Диск.
- Если видео очень большое — хранить в облаке (Яндекс Диск и т. п.), а в Битрикс положить ссылку.
